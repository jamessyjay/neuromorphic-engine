# Neuromorphic Engine - HOWTO Guide

This document describes how to run, test, and profile the engine on a local machine (Mac/PC) and how to connect the visualizer.

## 1. Running the Simulation (Benchmark Mode)

The primary way to run a stress test of the network. By default, it generates a network and simulates its activity.

```bash
# Basic run with default parameters (10,000 neurons)
cargo run --release -- --benchmark

# Run with custom parameters and reset the old save state (RECOMMENDED FOR TESTS)
cargo run --release -- --benchmark --neurons 100000 --synapses 1000000 --ticks 10000 --fresh
```

**Flags:**

- `--benchmark`: Enables stress testing mode.
- `--neurons N`: Number of neurons to generate.
- `--synapses N`: Number of initial synapses.
- `--ticks N`: How many ticks (milliseconds of biological time) to simulate.
- `--fresh`: Deletes the `brain_save.bin` file before starting to generate a new network instead of loading the old one.

---

## 2. Running with the Visualizer (UI Mode)

If you want to see how the network looks and operates in real-time in your browser:

### 1. First, start the engine with the `--ui` flag (this will spin up a WebSocket server on port 3030)

[!] (For the UI, it's highly recommended to use no more than 5,000-10,000 neurons, otherwise the browser's WebGL will lag heavily)

```bash
cargo run --release -- --benchmark --neurons 1000 --synapses 5000 --ticks 1000000 --fresh --ui
```

### 2. Open the visualizer file in your browser (Chrome / Safari)

Simply double-click the `visualizer/index.html` file or open it via Live Server.
It will automatically connect to `ws://127.0.0.1:3030` and start rendering the network.

---

## 3. Special Biological Testing Modes

The engine contains built-in scenarios for testing biological physics (Phase 8, Phase 24, etc.):

```bash
# Reflex Arc (Pain Sensor -> Interneuron -> Motor Neuron)
cargo run --release -- --reflex

# Inhibition Loop (Testing GABA receptors)
cargo run --release -- --inhibition

# Morphology Audit (Testing synaptic weight changes via STDP)
cargo run --release -- --morphology
```

After these tests complete, beautiful PNG graphs showing action potentials will be generated in the `graphs/` folder.

---

## 4. Running the Automated Architecture & Physics Test Suite

The engine includes a massive 7-block test suite (35+ tests) verifying everything from cellular metabolism (ATP, Hypoxia) and dendritic summation, to global network scaling limits ($O(n^2)$ bottlenecks) and memory boundaries.

To run the full suite:
```bash
cargo test
```

To run a specific test block and see detailed console logs (e.g. for low-level benching):
```bash
cargo test --test low_level_tests -- --nocapture
```

*For details on all test scenarios, refer to the [TESTS.md](TESTS.md) file.*

---

## 5. Running Micro-Benchmarks (Criterion)

If you modify physics or search algorithms and want to measure exactly how many microseconds a specific piece of code takes (e.g., microglia pruning or astrocyte cleanup):

```bash
cargo bench
```

This will run the test suite from the `benches/` folder.
*(If you need HTML graphs for the benchmarks, the results will be located in `target/criterion/report/index.html`)*

---

## 6. Where to Find Logs and Reports?

- **Brain Save:** `brain_save.bin` file in the project root. This is a binary dump of the entire network state.
- **Graphs (Voltage / Time):** In the `graphs/` folder. Generated by the `plotters` library after tests.
- **JSON Telemetry:** In the `reports/` folder (e.g., `simulation_report.json`). Contains a complete state dump of the network at the end of the simulation.

## 7. Compiling for Jetson (Hardware Deployment)

The current build on Mac uses the CPU (`par_iter` Rayon). To compile the native CUDA version:
Simply transfer the repository to a Jetson device (where `nvcc` and Ubuntu are installed) and run:

```bash
cargo build --release
```

The `build.rs` file will automatically detect the OS and compile `cuda/base_neuron.cu` for the GPU.
